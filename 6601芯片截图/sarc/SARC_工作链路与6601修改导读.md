## 2. 先分清控制器、采样通道和处理通道

LLD第2章把SARC的范围列为ADC工作模式配置和管理、数字校准、虚拟通道映射、优先级控制、采样触发控制、采样缓存处理、信号预处理、事件管理和中断上报。该处还明确：“当前版本sarc不支持差分模式，仅支持单端模式，但文档中仍保留相关差分内容。”不能因为后文保留了差分校准流程，就把它作为当前版本已支持功能。[来源R1]

| 原文对象 | 在工作链路中的位置 | 原文数量或关系 |
|---|---|---|
| ADC CORE／SARC控制器 | 模拟采样转换与数字控制对应 | LLD 5.1写2个ADC CORE、各对应1个SARC、各占一条AHB；第三组有删除标记。LRS FUNC01仍写3个内核，FUNC04/06写2个，两种记载不在此统一。 |
| 采样复用通道 | 选择采集哪一个模拟输入 | LRS FUNC02要求数字侧按32个采样通道预留控制接口，模拟侧按实际通道实现；不能据此认定有32个外部引脚。 |
| 虚拟通道VC | 保存采样参数并参与触发和调度 | 每个控制器16个VC；参数包括使能、优先级、S/H窗口、采样通道、触发源、触发方式等。 |
| 预处理通道PC | 用户偏置、增益处理 | 16个，与VC一一对应。 |
| 预处理滤波通道PFC | 用户预处理之后的可选滤波 | 8个，由16个预处理通道配置映射；FIR 1～8阶或直接1型IIR 1～4阶。 |
| 求和通道SCh | 过采求和结果处理 | 8个；LLD 5.15写在预处理滤波通道后，映射关系与预处理滤波一致。 |

## 4. 5.2～5.10：时钟、校准、触发和采样调度

### 4.1 先读使能及校准约束

LLD 5.2为时钟关系，5.3为SARADC CALC。实际使用前要同时读LRS 2.4的八条约束：数字控制器不能早于模拟ADC解复位或使能；系统时钟不能低于ADC工作时钟；外部采样触发须为宽度大于1个系统时钟周期的正脉冲；超过16阶FIR要求系统时钟大于ADC时钟2倍，并给出连续滤波采样的间隔要求；校准时先关闭模拟ADC使能，完成后再打开；修改VC配置先关对应vc_en，再配置并打开；控制器使能早于内部其他使能。[来源R3]

这只是约束入口，不是根据其他芯片寄存器编写的初始化程序。校准图中的系数、位宽和公式缺口仍按U06/U07/U10及LRS-U02保留。

### 4.2 一次触发怎样成为一次采样请求

LLD 5.4说明外部采样触发先在sarc_wrap取上升沿，再送到sarc_core，按16个VC的使能、触发源与触发模式产生有效触发。5.5区分两种模式：单次模式每次VC配置生效后仅响应一次；连续模式在VC_EN有效期间可重复响应触发。[来源R4]

LRS FUNC13进一步区分数字“连续触发”与模拟ADCCORE的模式：模拟ADCCORE固定为单次模式，数字侧每发一个start触发一次采样。因此，不能将数字连续触发解释成模拟核心无需再次start就一直自主转换。[来源R4]

### 4.3 Blanking、优先级和抢占不是同一件事

| 机制 | 已有原文说明 |
|---|---|
| Blanking，LLD 5.6 | 窗口内VC0可响应；其他VC触发等待窗口结束按优先级处理；窗口内重复的非专用触发告警并忽略重复触发。 |
| 优先级，LLD 5.7 | LRS FUNC10给出0～3四级，数值越小优先级越高；同级VC编号越小优先级越高。 |
| 同时触发冲突 | LRS FUNC12给出丢弃低优先级或全部排队两种可配置处理，默认排队。 |
| p0抢占 | LRS FUNC11明确仅p0可抢占其他低优先级，p0内部不抢占，有使能控制；高优先级结束后继续低优先级请求。 |
| 抢占后的请求恢复 | LLD原编号“1.1.1 抢占功能”写明：start后清flag；若抢占导致对应start无法返回ready，重新拉起flag；用对应ready指示请求完整结束。 |

交接区抢占还涉及`sarc_a2d_outrd_hold`，原文要求保证第一次ready/data返回时序。三处嵌入时序表U09仍限制逐拍判定，不能把上面的机制说明等同于已经核实全部抢占边沿。[来源R2、R4、R7]

### 4.4 同步与两类软件触发

LLD 5.8和LRS FUNC06说明两个ADC可用相同触发源进行同步或冗余采样，也可用不同触发源非同步采样。LLD 5.9和LRS FUNC15/16保留两种软件入口：一种直接控制VC开始采样，不经过采样触发信号；另一种软件输出触发，进入与硬件触发相同的选择通路。两者不能合成“同一种软件触发的两个名称”。[来源R4]

## 5. 5.11：触发到采样的延迟记录

LLD 5.11描述每个VC的Trigger-to-sample捕获：有效触发时锁存REQSTAMP，在采样开始时用计数值与REQSTAMP作差锁存DLYSTAMP。该处全局free-run计数器为12bit，原文提示超过4096个SYSCLK周期会得到错误延迟值；这是原文限制，不在此修正。[来源R8]

6601浅蓝续句分别规定：p0抢占后，低优先级在第二次采样开始时更新DLYSTAMP；过采启用时只在第一次开始时锁存延迟。LRS FUNC48的“不抢占4个ADCCLK以内、抢占6个ADCCLK以内”是需求指标，不是本仓库的实测成绩。[来源R8、R9]

## 6. 5.12～5.17：不要把两种滤波串成一条必经链

**已有文字明确支持两条结果路径的区分。** 下表是阅读索引，不是替代原图的重新设计框图。

| 路径或处理 | 输入与处理 | 对应结果／下游 |
|---|---|---|
| 数字校准，5.12 | 对模拟采样结果作数字偏置、增益校准 | 校准后的结果供后续处理。图中字形未确认的公式与范围仍见U10。 |
| 用户预处理，5.13 | 校准结果经过用户偏置／增益处理，16通道对应16个VC | 用户预处理结果可选地进入PFC；第一组结果寄存器承接该侧结果。 |
| 预处理滤波，5.14 | 16个PC配置映射到8个PFC；支持直接1型IIR 1～4阶或FIR 1～8阶 | LRS FUNC44规定未映射部分bypass；不是所有VC都必须进入PFC。 |
| 过采求和，5.15 | 对预处理滤波输出按过采次数求和 | 8个求和结果及其有效事件。 |
| 超门限检测，5.16 | 对用户预处理补偿后的采样结果进行上下门限独立检测 | 实时状态、事件、中断及DMA相关请求；不是第三组滤波结果。 |
| 滤波通道，5.17 | 输入明确为**校准补偿后的采样结果** | 8个FC，FIR最大32阶、IIR 1阶、滑动平均及非滑动平均；处理结果到第二组。 |

依据：LRS FUNC20～27、44，LLD 5.13～5.18。[来源R5、R6]

LLD 5.17还保留“6001是用户预处理补偿后结果，6002是校准补偿后结果”的历史区别，不能因为概括段落把几个处理名称并列，就把当前PFC、求和和FC都接成必须依次经过的串行链。S01影响该节IIR到滑动平均之间的来源连续性；本导读仅说明现有文字，不填入缺失段落。[来源R6、R12]

### 6.1 过采控制和求和侧分别做什么

LLD 5.15“过采控制侧”写8套间隔／次数配置；触发到来时加载影子配置；未到次数时自动按间隔拉起对应vc_flag；过采期间新触发被忽略但产生可清除告警。LRS FUNC47补充N≤16、间隔count为22bit且单位为sarc工作时钟、间隔期间允许其他低优先级采样。[来源R6、R9]

“求和侧”写按次数对PFC输出求和，并明确：“优先级冲突的处理，resume的恢复模式下，需清零求和结果”。因此这里只保留原名resume/conti及可见行为，**不按英语字面把resume重新解释为保留累计值继续**。原文还写可以复用扩展36bit加法器、完成后可输出中断／DMA请求，并有使能控制。[来源R6]

### 6.2 数据格式只按对应位置使用

| 原文位置 | 已写明的结果格式 |
|---|---|
| LRS FUNC25，第一组 | s(16,2)或s(15,0)。 |
| LRS FUNC25，第二组 | s(16,2)或u(12,0)。 |
| LRS FUNC25，求和 | 随第一组配置匹配为s(20,2)或s(19,0)。 |
| LLD 5.18，第一组 | s(16,2)与s(16,0)，括号另写实际s(15,0)有效和“最高两位均为符号位”。 |
| LLD 5.1数据格式说明 | 同类说明又写“最高位均为符号位”。 |

这些表述分别保存，不能由导读决定哪个位宽或符号位描述才是正确实现。s(a,b)、u(a,b)在LLD图5-3后定义：a为总位宽，b为小数位宽；signed情况总位宽包含符号位。[来源R2、R5、R10]

## 7. 5.18～5.22：结果、FIFO、EOC、中断和DMA

### 7.1 缓存和FIFO

LLD 5.18给出两组16×16bit结果和一组8×20bit求和结果，并列`result_ovf`、`result_val`、`result_data`。LRS FUNC25补充求和结果寄存器地址连续于两组结果；这些是布局关系，不是已取得6601完整地址表。[来源R5、R10]

LLD 5.19写两组结果分别通过bitmap映射为FIFO模式，参数独立配置；有效bitmap为`cfg_*_fifo_vc_sel & cfg_vc_en`，初始化或更新配置后需写1到bitmap_reload，采样顺序按bitmap中VC编号由小到大。LRS FUNC38～43补充深度、读取对应VC、清除val/ovf以及FIFO空满、溢出和数据个数状态。这里的两组FIFO不能推断成求和结果也自动有第三组FIFO。[来源R10]

### 7.2 EOC不应与结果有效事件混同

LRS INTR01列出三个可选EOC位置：S/H窗口结束、采样转换结束（默认）、S/H窗口开始。INTR02规定可配置16bit SYSCLK上沿延时；新的EOC到来而前次延时未完成时，输出前次触发并开始处理当前EOC，另有延时冲突告警与VC编号上报。[来源R9]

阅读提醒：既然原文允许EOC在S/H开始产生，不能把所有EOC一律当成结果已经写入寄存器。LRS INTR04也把EOC与结果寄存器有效分别列为中断源；这是已有条目的区分，不是新增设计要求。[来源R9]

### 7.3 中断、DMA和CPU_WRAP

| 部分 | 原文已经明确 | 不能由此推断 |
|---|---|---|
| 中断 | LRS为5路，LLD 5.20的6601段写1+4路：一路含上下门限源，另四套可从EOC、两组结果有效、求和结果有效中选源。 | 不能把5路总数本身当成6601新增5路；被删除的旧清单不当作未删要求。 |
| DMA | LRS FUNC30写4+1；LLD 5.21写4个可选请求通道，并保留6801增加超门限或事件的说明。FIFO非空也可选择到四个请求通道。 | 不把LRS“4+1”与LLD“4”静默改成统一数字。 |
| DMA握手 | LLD明确sarc只选择请求源输出，握手功能由DMA_MUX实现。 | 不把DMA数据搬运本身归为SARC内部功能。 |
| CPU_WRAP | LLD 5.22为减少CPU读取延迟同步采样结果，6601段明确“两组”、adcreg_receive调整交互和“所有逻辑在200M下”。 | 不把200M当实测值，不据正文补出U19未辨配置名、时钟图例和删除范围。 |

依据：LRS FUNC26、30、31及INTR04，LLD 5.20～5.22。[来源R9、R10、R11]

## 8. 6601修改从哪里看

完整原文、章节、颜色和原图均在两份正文第二部分及[修改点总览](SARC_6601修改点总览.md)。本轮在总览增加联合主题入口，便于把LRS需求与LLD实现说明对应起来，原有78个来源编号不增不减。

优先阅读：控制器及接口调整；p0抢占与ready/flag恢复；延迟捕获变化与时延指标；另一软件触发通路；过采控制、求和和结果；加法器及输出裁剪标记；中间值观测；中断／DMA求和源；CPU_WRAP；采样及blanking触发源表。[来源R2、R6～R11及修改点总览]

颜色按SARC原文声明判断浅蓝／清绿区域；6001/6002/6801历史说明、普通红字和辅助图中未核实版本的颜色不自动算6601新增。C11的遮挡和C46的图内标记缺口继续挂在原记录下，不因为已经能够讲清主体流程而标成完整。
