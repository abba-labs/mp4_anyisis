# AGENTS.md - ET6601 截图文档精准还原规范

本文档是本仓库所有 AI Agent、视觉识别脚本与自动化流程的刚性工作规范。

---

## 1. 唯一核心目标

本项目的目标只有一个：

> **把用户提供的原始截图，精准、完整、可追溯地还原成结构化 Markdown 技术文档。**

本项目不是 IP 研究项目，不负责推导设计意图、补充背景知识、分析架构优劣，也不根据模型知识改写原文。

允许输出的内容只有两类：

1. **截图原文还原**：标题、章节、正文、表格、接口、寄存器、图题、图注、公式、时序说明等。
2. **截图中明确存在的 ET6601 修改点**：仅针对继承 IP，根据截图里的下划线、颜色、修订文字、批注等视觉证据提取并归集。

严禁把模型推断、常识补全或“看起来应该如此”的内容写成原文。

---

## 2. 原始文档边界优先，禁止按截图或功能拆文档

### 2.1 基本原则

**一个原始文档 = 一个最终 Markdown 文档。**

截图可以为了处理方便临时分批、分目录保存，但最终输出必须恢复原始文档边界和原始阅读顺序。

禁止因为截图内容涉及不同功能模块，就把同一原始文档拆成多个独立文档。

### 2.2 CPLD_INTERFACE 特别规则

CPLD_INTERFACE 是 **一份完整文档**。

当前仓库中以下目录只是历史处理中按截图/工作表拆出的临时分组，**最终必须合并回同一个 CPLD_INTERFACE.md**：

- interface_cpld
- interface_cpld_cfg
- interface_cpld_crg
- interface_cpld_tcu
- interface_dma
- interface_efpga
- interface_efpga_cfg
- interface_int
- interface_ppi
- interface_test_pin

这些名称只能作为 CPLD_INTERFACE 文档内部的工作表/章节来源，不得继续被当成十份独立最终文档。

cpld_reg 和 ppi_doc 若原始来源本身是独立文档，则继续按独立文档恢复，不与 CPLD_INTERFACE 强行合并。

---

## 3. 新 IP 与继承 IP 的修改点规则

### 3.1 CPLD：新 IP

CPLD 是 ET6601 新 IP。

因此：

- 只做原始文档精准还原；
- **不建立“ET6601 修改点”章节；**
- 不写“未发现 ET6601 修改点”“属于标准基线”等推断性结论；
- 不与旧芯片做差异分析。

### 3.2 继承 IP

EFC、SARC、HAC_WRAP 等继承 IP，除原文还原外，还需要提取截图中**明确标出的** ET6601 修改点。

修改点必须满足：

- 有明确截图视觉证据；
- 能定位到截图文件；
- 尽量定位到原章节/表格/段落；
- 保留原意，不扩展“为什么改”“影响是什么”等截图未给出的分析。

修改点可标记为【新增】【修改】【删除/回退】【参数调整】，但分类必须由截图内容支持。

---

## 4. 精准还原规则

### 4.1 文本

- 不缩写、不概括、不润色。
- 原文有错别字时，不擅自“纠正”为常识版本；只有在截图足够清楚时按截图原文录入。
- 无法 100% 确认的字符不得猜测，使用“⚠️【待人工复核】原图此处无法确认：images/xxx.png”。
- 若只能确认部分内容，保留已确认部分，并明确未知位置。

### 4.2 表格

- 表头、列顺序、行顺序、单位、位宽、属性、默认值必须保留。
- 长表必须逐行恢复，禁止使用“略”“其余类似”“……”代替截图真实内容。
- 跨截图连续表格必须合并成一张逻辑连续的表，不能按截图编号切碎。
- 同一行跨截图或被画面裁切时，必须标注来源并等待后续截图补齐，不能自行补值。

### 4.3 双页截图

GameViewer 左右双页画面必须按原文阅读顺序恢复：

1. 左页；
2. 右页；
3. 再进入下一页。

禁止把同一横坐标上的左右页文字横向拼接。

### 4.4 图、框图、时序图

- 保留图号、图名、正文中对图的说明。
- 无法用文本等价恢复的复杂图，保留原图引用。
- 不根据模型理解自行重画、重构或补全信号。
- 若截图中的图能够清楚读出标签，可转录标签，但必须以原图为准。

### 4.5 非文档噪声必须删除

以下内容不得进入最终正文：

- ETMCU huan.li、姓名/录屏水印；
- 日期时间水印；
- GameViewer 翻页条、缩放比例；
- UDP、fps、Mbps、分辨率等推流信息；
- 鼠标、窗口控件、Excel 选中框等 UI 元素。

## 5. 最终 Markdown 结构

### 5.1 新 IP 文档（如 CPLD）

结构：

# [原始文档标题]

> 来源：原始截图还原
> 原图目录：...

## [原文第 1 章/工作表]
...

## [原文第 2 章/工作表]
...

**不添加 ET6601 修改点章节。**

### 5.2 继承 IP 文档

结构：

# [原始文档标题]

> 来源：原始截图还原
> 原图目录：...

## 第一部分：原始文档正文
...

## 第二部分：截图中明确标出的 ET6601 修改点

修改点至少记录：位置、类型、原文/变更内容、原图。

第二部分只能收录有原图证据的内容。

---

## 6. 验收标准

最终验收只看“还原是否可信”，不看是否做了额外技术分析。

必须满足：

1. **不漏**：截图里的正文、表格、接口、寄存器、图题、修改标记不应遗漏。
2. **不乱**：章节顺序、表格顺序、左右页顺序、跨截图连续关系正确。
3. **不加**：不得加入截图没有的技术结论、背景解释或推断。
4. **不猜**：不确定内容必须标记待复核。
5. **不脏**：水印、播放器信息、时间戳、UI 控件等必须剔除。
6. **可追溯**：修改点和模糊项能够回到具体原始截图。
7. **文档边界正确**：不能把同一原始文档按功能或截图人为拆散。

> 最终判断标准：拿 Markdown 与原截图逐页对照，内容不能少、不能乱、不能凭空增加；继承 IP 中截图明确表达的 ET6601 修改点不能漏。
