# AGENTS.md - ET6601 截图精准还原工作规范

本文档是 `6601芯片截图/` 下所有截图还原工作的强制规则。

## 1. 唯一工作目标

本仓库的目标只有一个：

> **把原始截图精准、完整、可追溯地还原成 Markdown 文档。**

本任务不是 IP 研究、架构分析、验证设计或技术总结。Agent 不得依据常识、其他芯片资料或自身理解补充截图中不存在的内容。

最终验收方式是：**Markdown 与原始截图逐页对照，内容不能少、不能乱、不能臆造；截图明确标出的修改点不能漏。**

## 2. 原始文档边界必须保持

必须按照“原始文档”而不是“截图批次/接口类别”组织最终文档。

- 一份原始文档 = 一份最终 Markdown。
- 处理过程中可以临时分批识别，但交付前必须恢复为原始文档边界。
- 禁止为了 OCR 方便把一份文档拆成多个独立文档。
- **`CPLD_INTERFACE` 是一份完整文档，不能拆成 `interface_cpld`、`interface_dma`、`interface_efpga`、`interface_ppi` 等独立最终文档。**
- `CPLD_REG`、`CPLD PPI说明文档` 等原本就是独立文档的，保持独立。

目标目录示例：

```text
6601芯片截图/
├── AGENTS.md
├── cpld/
│   ├── cpld_interface/
│   │   ├── images/
│   │   └── docs/
│   │       └── CPLD_INTERFACE.md
│   ├── cpld_reg/
│   │   ├── images/
│   │   └── docs/
│   └── ppi_doc/
│       ├── images/
│       └── docs/
├── efc/
├── sarc/
└── hac_wrap/
```

旧的拆分目录在迁移完成前只视为**临时来源目录**，不能作为最终文档边界。

## 3. 精准还原规则

### 3.1 忠实原文

必须恢复截图中的：

- 文档标题、章节标题、编号和层级；
- 正文段落；
- 表格全部行列；
- 接口列表、信号名、方向、位宽、连接关系、说明；
- 寄存器表、字段、地址、默认值、属性；
- 图号、图名、图注；
- 状态机、时序图、框图旁的文字说明；
- 修订记录和截图中属于原文的批注。

禁止：

- 省略长表；
- 用“同上”“略”“其余类似”等替代原文；
- 主观润色技术表述；
- 根据上下文猜测缺字；
- 自动“修正”原文中的设计内容；
- 把不同截图的内容按 OCR 输出顺序随意拼接。

### 3.2 阅读顺序

- 双页截图按原文真实阅读顺序恢复：左页完成后再右页。
- 跨截图连续表格、段落和章节必须正确续接。
- 最终 Markdown 按原始文档页序/章节顺序组织，不按图片文件名排序，也不按 Agent 处理先后排序。

### 3.3 去除非文档噪声

以下内容不属于原文，必须剔除：

- `ETMCU huan.li`、`BTMCU` 等录屏/账号水印；
- 日期时间叠加；
- `1080F`、`fps`、`Mbps`、`4K auto`、缩放比例等播放器/采集信息；
- 翻页控件、窗口边框、系统 UI；
- OCR 由水印造成的碎片字符。

只有当这些文字本身确实属于文档正文时才保留。

### 3.4 无法确认的内容

看不清就不能猜。

统一写法：

```markdown
> ⚠️ 原图待复核：该处无法从当前截图 100% 确认。
> 原图：images/<filename>.png
```

若有候选识别，只能写“疑似”，不得作为确定正文写入。

### 3.5 图、框图、时序图

能准确转成文字/表格的内容应转录；无法等价文本化的复杂图必须：

1. 保留原图号；
2. 保留原图名；
3. 保留截图中可确认的图内标签；
4. 引用对应原始截图；
5. 不凭空重画、不自行解释图意。

## 4. 修改点提取规则

### 4.1 CPLD

**CPLD 是 ET6601 新 IP，不做“相对旧 IP 的修改点总结”。**

CPLD 任务仅为精准还原原始文档。最终 `CPLD_INTERFACE.md`、`CPLD_REG` 等文档中不得机械加入“ET6601 专项修改点”章节。

### 4.2 继承 IP

EFC、SARC、HAC_WRAP 等继承 IP，在精准还原正文之外，需要把**截图本身明确表达的 ET6601 修改点**单独汇总。

只允许依据：

- 明确的 `ET6601` / `6601` 修订文字；
- 下划线、颜色、高亮等截图中可确认的变更标记；
- 明确写出的“新增/删除/修改/回退/此处修改”等原文；
- 修订记录中的明确差异说明。

禁止依据技术推理自行判断“这应该是 ET6601 修改”。

每条修改点必须带：

- 原始文字；
- 所在章节/表格；
- 原图文件名；
- 修改性质（只有原图能明确判断时才标注）。

## 5. 最终文档结构

### 5.1 CPLD 等新 IP

```markdown
# 原始文档标题

> 来源：原始截图精准还原。
> 无法确认处均保留原图引用，不做推测。

[按原始文档顺序完整恢复正文]
```

不要额外添加“修改点总结”。

### 5.2 继承 IP

```markdown
# 原始文档标题

## 第一部分：原始文档精准还原

[按原文顺序完整恢复]

## 第二部分：截图明确标注的 ET6601 修改点

[逐条列出，并回链原图]
```

第二部分只做截图事实归集，不做 IP 研究和原因分析。

## 6. 质量门禁

一份文档只有同时满足以下条件才算完成：

- [ ] 原始截图数量已盘点；
- [ ] 截图阅读顺序已确认；
- [ ] 原始文档边界正确；
- [ ] 标题/章节顺序与原文一致；
- [ ] 正文无明显漏段；
- [ ] 表格无抽样、省略；
- [ ] 信号/寄存器名称逐项核对；
- [ ] 水印和播放器噪声已清除；
- [ ] 模糊处没有猜测；
- [ ] 图表均能追溯到原截图；
- [ ] CPLD 未生成无意义的“修改点”章节；
- [ ] 继承 IP 的明确修改点已逐条提取；
- [ ] 最终 Markdown 可由截图逐页复核。

## 7. 当前整改优先级

1. 修复 `CPLD_INTERFACE` 被拆散的问题，恢复成一份完整文档；
2. 清除 CPLD 各临时文档中错误的“ET6601 专项修改点”章节；
3. 对 CPLD_INTERFACE 做逐截图精校；
4. 对 EFC 做正文精校和明确修改点提取；
5. 对 SARC 做正文精校和明确修改点提取；
6. 对 HAC_WRAP 做正文精校和明确修改点提取。

**准确性优先于速度。无法确认的内容宁可标记待复核，也不能编造。**
