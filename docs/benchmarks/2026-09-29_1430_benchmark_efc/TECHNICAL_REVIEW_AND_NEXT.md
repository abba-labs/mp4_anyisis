## 2. 两个关键判断

### 2.1 不能只优化一半链路

暂按工具2149秒、Agent复核1800秒估计，两段约占总时间54.4%和45.6%。即使工具处理不花时间，总工作流仍约30分钟；只让复核不花时间，仍需35.8分钟。这只是基于报告估算的瓶颈推理，不是吞吐实测，也没有证明1800秒都是模型计算。

因此主方向是同时减少工具重复工作和复核交互开销，不是立即换OCR、再调一个字符或先买GPU。

### 2.2 先从现有记录取得耗时归属，不让诊断成为新的停工阶段

当前parser.py已经在每个实际解析输入的adapter.json中保存initialization_seconds、inference_seconds、export_seconds。测试机可以直接汇总本次EFC已有tool/native/*/adapter.json及report.json，不需要为获取这些字段重跑35分钟。

必须同时记录实际解析输入数、输入图尺寸/累计像素、成功/失败/缓存命中、拼接尝试/拒绝/回退、输出文件数、实际设备和线程。汇总以本次真实执行的唯一job为单位：缓存文件可能保存历史计时，不能把缓存命中的旧推理时间加成本次耗时；失败调用没有完整adapter时，要从日志单列缺口。串行求和与墙钟时间不同，未覆盖时间只叫unattributed，不直接全部归给拼接。Paddle导入、构造时补丁、解码和索引等也可能在这些计时字段之外。

如果旧日志缺失，就保留2149秒为历史报告值，下一次完整运行补齐测量；不补造时间戳。阶段汇总是下一完整任务的开头，不另交一份报告后等待ChatGPT批准。

## 3. 技术突破方向：缩减重复处理，再按证据用现成加速

### 方向一：由重复画面转成有来源的资料区域，最终统一导出

源码事实：video.py对选中帧使用有重叠的SCANS分组；parser.py对每个job做完整解析，并在word=True时逐job执行save_to_word。其engine通常只初始化一次，不应错误地把问题说成每帧重新加载模型。mobile只显式替换OCR检测和识别模型，不代表整条版面/表格链路都已轻量化。

下一候选保持PP-StructureV3与现有模块，优先实现：

- 明确实际文档视口，保留完整源帧/坐标；工具栏和窗口外区域不送入昂贵解析，但不得裁去真正正文、表头或页边资料。
- 利用已有源映射和OpenCV能力组织相同页的重复观察；完整单帧已经容纳的图表优先直接保留，需要跨屏时才拼。去重是带来源的任务合并，不是删源图。
- 相似哈希/场景阈值只做候选；必须防止一位地址变化、跨页相同文字和短暂画面被合并。没有可靠位置/内容证据就保留任务及未决范围，不为了少job漏资料。
- 保留JSON/Markdown/表格/原图作为初稿与中间证据；能安全延后的逐观察Word改在资料组织后统一导出，A/B用相同转换路径比较。不能伪造native adapter喂给既有Word入口，复用公共转换能力即可。
- 在复核任务中保留原图上下文与原分辨率文字/表格区域，不用把整页压小来取得虚假速度。

这些是待实测的优化方向，不是本轮已经证明的35.8分钟根因。不要预设视频时长等于应有页数，也不要规定必须将job数量压到某个数才通过。

### 方向二：把Agent看图变成可重放的批量资料任务

不要求更换已经可用的视觉通道。程序生成稳定unit/evidence/target ID、初稿、上下文图和必要清晰裁图；Agent或现有获准API连续消费任务，只返回差异/覆盖/未决，程序统一校验、应用和导出。模型不反复抄全文、不同时把生成与评测答案放在一个上下文里。

结果文件与输入hash、模型身份、提示模板和处理参数绑定，防止复用过期意见。每项保存真实开始/结束、图片数量、成功/重试/未决和原始意见；API有usage才保存usage，Agent工具看图不能虚构API或Token账单。能取得准确模型身份就记录，不能取得写unknown。

初期所有关键字段进行独立源读取，包括未修改字段；没有独立上下文证据就明确区分自查和独立复核。先完整覆盖全部资料单元，疑点有限复查，其他单元继续。不增加多Agent调度平台、数据库或消息队列。

水印污染先作为派生文字归属问题处理：结合源坐标、方向及上下文核验后从正文排除并留痕，不擦除原图水印，不把保密等级、源文档页头或合法正文一并删掉。不得用固定字符串黑名单或按名字/标识符模式硬替换。

表格乱码不等于整行可删除。先核对原格是否为空及行列位置；保留真实空行和合并关系。错误结构交现有结构能力处理或标未决，不自写分格求解器。

图片任务以源图完整保留、无裁断/接缝损伤为判断；没有将图内文字全部转成可编辑文本，本身不是图片恢复失败，除非用户另要求图形语义转录。避免把任务扩展为重绘全部架构图。

### 方向三：仅在推理确为大头时启用上游现成加速

固定PaddleOCR v3.7.0官方高性能推理文档提供enable_hpi、Paddle Inference/OpenVINO/ONNX Runtime/TensorRT等路径；接口存在不证明测试机模型组合兼容，更不证明本项目可加速多少。已有MKLDNN配置不要当作新成果。

有已配置可用GPU时可同环境单列设备对照；CPU场景先核对实际核心配额、线程和占用，再决定是否测试上游HPI。隔离依赖，不在旧OCR环境直接升级或自动拉全套新服务。换推理执行器不等于换文档解析后端，但必须保留真实模型/参数/环境身份并比较内容误差。

当前不默认采购硬件、不新建视觉供应商、不展开后端排行榜；这些不是补全本轮数字的前提。

## 4. 下一轮只交一个完整任务包

**目标：同一份153.733333秒EFC视频，得到可取回A/B结果、可计算质量数字和一个加速候选的完整数据。** 测试端自行完成接线、实现、运行、评分和提交，普通步骤不回聊天等批准。

1. 从已存在的EFC运行目录汇总第2节数据，归档A、B或受授权持久链接、逐项来源/修正记录。已有B若只做了样本，就标B_partial，不冒称全片完成；已有B不存在可重放成品时，后续生成的完整B属于新执行，不能回填成原65分钟结果。
2. 冻结已有A/B。补齐同源样本的真实转录与成品读取值，直接计算现有样本的数值；再按预先固定的前中后/章节分层扩展至原任务预算（30段正文、100格、50个技术字段、5图，确实不足则全查并记总量）。已知错误样本单列exploratory，不用它们估算全片错误率。
3. 根据现成耗时分解选择方向一/二中的实际高开销点，组成一套加速候选C；同一视频从MP4开始在独立新数据目录执行一次，复用权重而非旧job结果。输入去重/延后输出和批量复核优先，HPI仅在证据支持且环境已可用时加作单独配置，不无限排列组合。
4. 连续完成全片优化/导出，冻结C后对同一独立源样本评分；遇到内容错误记账继续，不边评分边修成PASS。不把降低覆盖或删除困难资料算加速。
5. 一次交付完整数据与候选，A/B/C均可不合格。只有阶段耗时支持、相同源范围和质量条件相当，才给出可信加速结论；没有严格控制单变量时，只报告整套候选效果，不把收益归因给某个局部更改。

旧A不用重跑来补资料；本轮允许为加速候选做一次新的完整测试，不覆盖本次EFC或旧SARC缓存。若超出当前会话执行窗口，保存同RUN断点和已完成范围，不重新初始化或换样本。

## 5. 这轮数据表必须真能算

| 指标 | 必须保存的数值/依据 |
|---|---|
| 字符错误率CER | 每个源样本参考、实际A/B/C文字、S/D/I及参考字符数；汇总CER=(S+D+I)/N，缺段计D、额外文字计I；仅统一约定的排版空白，关键标识符保留原样；有意义的空格错误另列 |
| 关键字段 | 同一源位置严格正确数/样本数；错误/缺失/源不可判定/输出未决分别列出，不把人名等普通文字充作寄存器字段凑量 |
| 表格 | 内容与行列/合并位置同时正确的格数/样本格数；整表结构正确数、额外行列、真实空行保留分别统计 |
| 覆盖和图像 | 全片源单元总数、已经处理/遗漏/未决/重复；图像完整保留数/抽检数；源清单不完整时不伪称全量覆盖 |
| 修正损益 | A错→B或C对、A对→B或C错、仍错、未决，均带计数，不用“已修正”代替 |
| 运行效率 | 各阶段墙钟时间，原生逐job耗时，输入/拼接/输出数量和像素量、设备/线程、重试、缓存；总耗时/视频时长；准备开发和独立评测另记 |
| 模型费用 | 实际请求及可观测usage；有供应商/型号/计费数据才按执行日官方或合同价计算。订阅未计量继续null，单列订阅背景和未观测原因，不写0或按看图次数猜Token |

通过率要报告分子/分母与范围，不能仅给low/high/corrected。评测从实际文件读取，不只比较脚本内存预期。源参考与A/B/C隔离；只有另一模型意见而未形成可靠源标准时写初步模型核对估计，不冒称可靠真值。

评测结果来自现有文件，冻结后不再让优化模型按评分答案修补；后续迭代另立版本。首次3/8/12/2之外新增样本不是原来预先选好的样本，要记录补充抽样时间和方法，不能伪造预注册。

完整任务新归档到docs/benchmarks/<新RUN_ID>/；原4文件不改。至少给出实际可取回的outputs/或产物manifest、质量明细、机器生成的数值metrics、阶段时间、真实调用/意见记录及运行命令。格式可复用现有JSON/JSONL，不增加框架。大文件只能用已授权存储，不能只给临时绝对路径，无法集中归档明确写缺口。

ChatGPT本轮不做小代码开发或重新跑基准；我负责本页路线与证据判断。测试端完整执行，一轮汇报数据表、最大成本阶段、三类实际错误分布和可运行产物，不再汇报单个标点通过。

不改main、不强推、不合并/改PR、不改工作流；不覆盖原图、原native和旧报告，不外发到新供应商，不索取或记录令牌。不以停用正确性检查换性能。当前测试不要求全片PASS才结束，坏结果同样应交付。
