# MP4 Video-to-Document Analysis & Reconstruction Pipeline (mp4_analysis)

> 面向高安全隔离内网、远程桌面与技术白皮书的**滚屏录屏逆向文档重构引擎**。

---

## 一、项目背景与现状

在芯片设计、金融核心系统及涉密研发局域网环境中，由于安全沙箱、Citrix/云桌面和企业级 DLP 防泄密策略，常规的底层自动化机制（如 Windows UI Automation、pywinauto、DOM 抓取或直接文件传输）**被严格隔离或禁用**。

研发工程师获取这些内网中的高精度设计规约（Design Specs）或寄存器映射表（MemoryMap）的唯一可行通道是**屏幕视觉捕获**。而传统的人工截图拼图极为耗时（一份 40~50 页的文档需耗费数小时人工）。

本项目探索并构建了一套**基于屏幕录屏（MP4 视频流）的端到端高保真文档逆向还原流水线**。当前项目已完成验证并封装的核心能力包括：
1. **毫秒级流式锐度抽帧**（从 4000+ 冗余视频帧中提纯无模糊关键帧）；
2. **1D 垂直模板互相关无缝拼接**（彻底解决跨帧超长图截断/腰斩问题）；
3. **滑动窗口连续流式文本去重**（解决逐屏滚动下的文字冗余与子条款丢漏）；
4. **工业级 OpenXML (.docx / .xlsx) 结构化渲染**。

---

## 二、我们分析的是什么样的视频？

本项目针对的技术录屏具有以下极其严苛的工业级特征：

1. **内容载体复杂**：
   - 并非简单的幻灯片或 PPT 切换，而是**连续垂直纵向滚动的复杂长文档**（如 46 页的芯片《EFC 详细设计文档》、16 页的《SARC 模块 LRS 设计规格》、上百行的《MemoryMap》硬件地址分配表）。
2. **多模态高度密集**：
   - **文字与多级缩进条款**：大量的需求子项（如 `a) b) c) d) e) f) g)` 细分约束）；
   - **高精度硬件表格**：数十行的 AXI/APB 总线信号表、触发源映射位域（如 `[109:0]`）、寄存器位段定义；
   - **跨屏超长图形**：高达 1000~1600 像素的巨幅时序交互图（Power On/Off、芯片 Boot 流程）、状态转移图、模拟与数字混合电路架构图；
   - **Verilog RTL 源码段**：带语法高亮的代码段落。
3. **环境强噪点干扰**：
   - 全屏布满半透明倾斜文字水印（如 `ETMCU huan.li 2026-09-27`）；
   - 滚动过程中伴随 H.264 视频有损压缩块效应、文字边缘抗锯齿模糊以及不均匀的鼠标滚轮加速度。

## 三、研发过程中攻克的核心困难

| 序号 | 核心技术难点 | 传统方案的缺陷 | 本项目的算法解决方案 |
| :--- | :--- | :--- | :--- |
| **1** | **视频帧数据极端冗余 (95%+)** | 盲目抽帧会导致几千张图，算力和存储当场爆炸 | **流式拉普拉斯方差算子 (Laplacian Variance)**：仅在内存保留 2 帧，差分识别滚动停顿点，并在停顿区间内锁定高频能量最大（边缘最锐利）的一帧，7 秒内将 4612 帧精炼为清晰关键帧。 |
| **2** | **超长图跨帧截断（图只显示一半）** | 单帧屏幕仅 750px，而流程图高达 1600px，单帧截图导致图纸被横向切断 | **1D 垂直归一化互相关 (NCC) 模板匹配**：利用屏幕滚动的纯 Y 轴平移物理特性，以 1 像素精度垂直缝合多帧重合带，还原 100% 全貌长图；对超大图按逻辑阶段自适应双分屏排布，防止 Word 等比缩放失真。 |
| **3** | **流式滚动文本去重与保真** | 传统关键词过滤容易过度概括，丢失 `a) b) c)` 等关键子条款 | **滑动窗口连续流式去重器**：建立时间空间平移队列，逐行消除重合带，提取 1000+ 行全量原生技术文本，杜绝 AI 总结省略。 |
| **4** | **芯片级零容错要求** | 错一个 16 进制字符（`0` 认成 `8`）或位宽导致芯片流片失败 | **双引擎交叉校验 (RapidOCR + VLM)**：本地高精 OCR 咬死字符细节与位宽，大模型负责版面宏观审校与架构组装。 |

## 四、目前面临的挑战与攻坚方向

虽然当前流水线已能成功跑通 40+ 页文档并输出完整 Word/Excel，但在实现**“全自动黑盒（任给一个视频均 100% 自动吐出完美文档）”**的终极目标上，仍面临以下关键挑战：

1. **复杂表格的跨帧垂直缝合与语义重构**：
   - 当一个几百行的表格跨越多个屏幕滚动时，表头只出现在第一帧，后续帧全是无表头的中间行。目前需要更强健的自适应表头保持与单元格矩阵重建算法。
2. **真正通用的自动模态路由（Modality Routing）**：
   - 传统版面分析（Layout Analysis）模型容易将带边框的长表格误判为 `figure`，或将带缩进的代码段误判为普通文本。需要构建专门针对技术文档的轻量级先验分类器。
3. **非均匀滚动与快速拖拽的动态自适应**：
   - 当人工录屏出现快速拖拽滚动条（发生剧烈跳变而非连续滚轮滑动）时，相邻帧可能出现重叠区域不足 10% 的情况，需要引入自适应回溯与光流补偿。

## 五、项目工程结构

```
mp4_analysis/
├── src/
│   ├── stream_extractor.py       # 流式拉普拉斯锐度抽帧核心
│   ├── vertical_stitcher.py      # 1D 垂直互相关超长图无缝拼接引擎
│   ├── stream_text_dedup.py      # 滑动窗口流式文本无损去重引擎
│   └── document_builder.py       # 工业级 Word / Excel 二进制编译渲染器
├── docs/
│   ├── architecture.md           # 完整架构设计与数学对齐原理
│   └── challenges_and_roadmap.md # 极端工况分析与后续演进路线
├── README.md                     # 项目技术白皮书
└── .gitignore                    # 忽略大视频与涉密临时文件
```
