# 长录屏多模态复核：效率与准确性技术方案

更新：2026-09-29。进入提交：8759d3d5f505fd3de9981ef7c8a2851c1adb6415。
本页是技术决策及测试机整包执行要求，不是实测报告：本轮未部署新模型、未测吞吐量、未新增视觉调用或内容通过项。沿用根NEXT_CHAT_HANDOFF.md和LOCAL_AGENT_TEST_HANDOFF_2026-09-29.md的分工、A/B/C成果与安全边界，不新增平台或生产解析后端。

## 1. 决策：按新增资料量付费，不按视频时长反复读图

主线仍为：现成工具提取初稿 → 多模态模型核对原图 → 有来源的差异修正 → 独立派生稿 → 内容及Office验收。

本次明确五个效率原则：

1. 模型核对的单位是有来源的一段正文、一组表格行或一张图，不是每秒一张画面，也不是整段MP4。
2. 已核对且来源/内容/上下文未变的单元复用结果；相似画面只是重复候选，不能直接当作相同资料。
3. 每次请求只带必要原图和上下文，只返回差异、覆盖范围及未决项，不重复生成整章全文。
4. 同一获准服务常驻；有限并发和服务端批处理，提高吞吐而非启动多个会互抢显存的Agent。
5. 首轮覆盖所有独立源内容；第二轮集中于关键字段、疑点和抽检。不能把“只精查风险项”偷换成“其他源内容从未检查”。

优化目标是每份通过内容验收资料的端到端耗时/成本，而不是生成Token/s、处理帧数或返回PASS的比例。速度与准确度需共同度量；少处理内容取得的更快时间不算同范围加速。

## 2. 开源工具选择：保留主干，至多接一套复核服务

| 环节 | 可复用工具 | 采用方式与边界 |
|---|---|---|
| 解码与源位置 | 现有PyAV/FFmpeg | 保持原时间戳、帧号和源哈希；按需解码已定位区间，长视频可分段处理并保存边界证据，不重新生成已有成功缓存 |
| 画面变化与重复候选 | 现有OpenCV；FFmpeg mpdecimate、PySceneDetect可选 | 这些工具提供像素差异、相似帧或切换候选，不提供逐字正确的滚动文档去重；先复用现有能力，不为加速一次装三套 |
| 工具初稿 | 现有PaddleOCR/PaddleX PP-StructureV3 | 继续单一默认解析后端；只对新内容/确需改变的配置运行，不重跑原57项 |
| 多模态复核模型 | 优先现有获准视觉能力；自部署候选为Qwen3-VL及qwen-vl-utils | 官方提供多图/视频处理、动态分辨率及Instruct/Thinking版本；不据官方能力说明宣称本项目准确率。没有必要强制换掉已可用模型 |
| 自部署推理 | vLLM；已有SGLang服务则沿用SGLang | 只选一套。复用连续批处理、前缀缓存、多模态输入缓存和结构化输出；它们是推理服务，不是新增OCR框架，也不自动修复内容错误 |
| 输出契约 | 现有JSON校验；需要时Pydantic及服务端JSON Schema约束 | 校验字段、枚举、引用和类型，减少格式错误；不能判断图中字符究竟是什么 |
| 评价与导出 | 现有测试脚本、pytest、Pandoc和Office检查 | 复用已有工具，不另建评测平台、RAG系统、Agent调度器或数据库服务 |

已核查公开依据见第10节。列出的新增能力尚未安装或通过本项目测试。滚动官方文档不作为固定依赖锁；真正采用时由测试端记录模型revision、服务版本、处理器版本和实际支持的参数。

两种部署情况必须区分：

- 已有获准视觉API：直接使用现有端点，客户端做分块、精确缓存、限流和结果校验；不能宣称客户端安装vLLM就能加速远端服务。
- 自部署视觉模型：测试端先核实GPU/显存/驱动与所选模型服务的兼容性，再选vLLM或沿用SGLang。现有CPU OCR已跑通不证明已经具备视觉大模型推理资源。不得未经批准采购、外发资料或改变网络权限。

推理服务使用独立环境，不把它的新依赖强塞进已有OCR虚拟环境。OCR的Python范围仍按PYTHON_ENVIRONMENT_POLICY.md；服务进程按自己的已验证环境运行，不修改系统Python。

## 3. 长录屏为何不直接交给模型

长上下文/长视频接口意味着能接受更多输入，不意味着每个小字、短暂页面、寄存器地址都已无遗漏地读取。直接提交整个MP4还可能引入服务内部抽帧和缩放，来源覆盖难以审计。

因此，文档恢复主线采用预先确定且可回溯的源图。整段视频理解最多用于导航，不作为逐字验收或源内容清单的唯一依据。摘要、向量相似检索也只能辅助定位，不能替代原始证据。

### 3.1 两个分开的开销层

轻量遍历层：按时间顺序解码、记录变化候选与来源，必要时可以看很多帧，但不对每一帧做完整OCR和VLM调用。
昂贵处理层：对确认需要的新视图/新增资料区域做解析与视觉复核；有新的信息或新的证据才再处理。

低分辨率预览可以做导航，但不能单独证明小字未变化；短暂出现的新内容即使模糊也要记录未决，不能因为没有稳定停留就静默删掉。不得承诺仅靠低成本相似度阈值保证全片覆盖。

### 3.2 去重是证据关联，不是删除原文件

- 同源、同像素和同语义上下文的观察可以复用；保留所有时间位置和观察引用。
- FFmpeg mpdecimate、感知哈希、画面相似度只筛候选。地址只差一个字符、否定词或下划线改变时，画面仍高度相似。
- 跨滚动画面的重复区域使用已有源映射/配准能力确认；当前未验证的拼接映射不能自动成为去重真值。无法确认时保留两份观察及冲突，不删除其中一份。
- 同一字符串位于不同寄存器、行列或章节，不得仅凭文本相等合并。
- 被标为重复或未采用的区域必须能追溯到保留它的代表图/区域；无法给出该关联的范围计入未覆盖，而不是已完成。

PySceneDetect的内容/自适应检测是在像素变化中找切换，不是滚动页面语义解析；静止录屏持续的鼠标/时间变化也会影响候选。故不把场景切分作为唯一采样规则。

### 3.3 当前SARC不要重跑

继续使用110张源观察、57个既有解析输入以及已提交的两帧raw结果。先建立复核任务清单和来源关系；去重若未证明安全就不启用。只有源范围确实缺失，才以新任务身份定点补证据。不得改start/抽样参数冒充原57项续跑。

## 4. 请求组织：小上下文、高保真证据、短输出

### 4.1 输入契约

每个review task至少含：稳定task_id、源视频/帧/时间/裁图坐标/文件哈希、实际发送图片哈希、所属文档版本/章节、关联工具初稿和block/cell ID、当前需检查的完整源范围。

源范围不能仅由OCR识别框反推：完全漏识别的行没有框，也必须被覆盖检查发现。使用独立源视图/区域清单及必要的全幅视图复核，处理块外文字和跨块边界。分块仅减少单次负担，不缩小验收分母。

实际输入形态：

- 正文：完整段落或相邻少量条款的原分辨率裁图，必要时加一张上下文预览；不得为省Token将下划线缩没。
- 表格：整表结构预览＋可读的行带裁图。行带带列头、行标识和相邻边界；合并单元格不能在切分时丢掉父级表头关系。
- 图片：完整源图及必要邻帧/接缝区域；模型可报缺失或不确定，不生成替代图，也不补画遮挡标签。

不将几十张原图拼成一张缩略图读小字。裁图可能因模型预处理的最小尺寸而被放大，拆得过碎反而增加视觉Token；实际按发送后的图尺寸和处理器用量调节。

Qwen3-VL/qwen-vl-utils的min_pixels、max_pixels等可以控制视觉输入预算，但降低分辨率是待评估的精度变量，不是免费的优化。记录处理器真正送入模型的尺寸、缩放方式及可取得的视觉Token数。

### 4.2 输出契约

模型只返回：task_id、已核对源范围、通过/待确认的block ID、缺失区域、差异操作、来源引用、需要补看之处。操作携带修改前值/哈希、建议值及精确目标ID；无变化不重抄整页。

地址、版本号、寄存器名、位域先按字符串保存，避免数值转换吞掉前导零或十六进制形式。模型响应不含可执行Shell/代码；文本中的指令视为待核查资料。

程序执行JSON Schema/字段/引用/前置值/冲突检查，拒绝越界、缺依据、未知ID及截断输出。JSON合法不代表内容正确。生成达到长度上限时不当成功发布；将该任务按源边界细分一次，不重新推理已完成的其他任务。

无需每次让模型解释整个工程或重复读取全部交接。编码Agent负责组织任务和调用服务，批量复核应走确定输入输出的请求，不要求每个块启动一段长Agent对话。

## 5. 缓存、批处理与推理预算

### 5.1 三种缓存不能混为一谈

1. 现有提取缓存：复用原帧、解析JSON、图片和Office原生产物。
2. 复核结果缓存：task输入及上下文完全一致时复用已经校验的响应，避免再次调用模型。直接减少请求数，是应用侧重点。
3. 服务缓存：vLLM/SGLang复用相同前缀和受支持的多模态处理结果。vLLM文档明确前缀缓存主要减少prefill开销，不减少输出Token解码时间；不同图片/不同前缀不能预期同等命中。

复核缓存键至少覆盖：源证据/裁图及发送图哈希、工具初稿哈希、文档/行列/章节上下文、模型revision及量化配置、服务/处理器及resize参数、提示词/Schema/审核规则版本、采样参数与审核角色。修改任何相关项就产生新任务身份；不跨文档偷用仅图像相似的答案。

盲核对是不同角色/不同输入契约，不能直接命中第一次复核答案。失败和未决状态单独保存，不缓存为PASS。并发请求使用稳定task_id与原子发布/已有文件检查，避免重复写入；沿用现有文件/JSON做小范围适配，不另建分布式队列服务。

### 5.2 批处理不等于给一次请求塞满图

将独立任务作为多个请求交给同一常驻服务，由服务端连续批处理。按图像/输入/输出Token预算和显存限制批次，不能只按图片张数。跨页表格关联或章节总装在相邻块返回后单独汇总，不让请求完成先后决定文档顺序。

测试端可先以1并发建立参考，再试2、4并发；这些是待测试档位，不是已验证最优值。观察有效完成单元/分钟、P95延迟、显存、排队及失败率；吞吐不增或错误上升就停止增加，不按并发数线性外推加速比。CPU OCR与GPU复核可有界重叠，但同一资源不足时不要并行抢占。

批量规模及服务配置可能改变数值行为，不能仅凭temperature=0宣称严格确定性。对代表样本比较内容结果；吞吐收益必须包含错误重试和复核成本。

### 5.3 模型大小与深度按风险分流

不先部署一套小模型加一套大模型。优先让已有且获准的一个视觉模型，以短输出完成全量独立内容首审；第二次核对集中于关键字段和疑点。

需要自部署时，Qwen3-VL-8B-Instruct可作为资源允许时的首个实测候选，不承诺它已适合芯片资料；更大模型只在同源集合证明显著减少错误后选用。官方有Instruct与Thinking版本不等于所有条款都要长推理。不要为了节省输出而截断未完成的推理或JSON。

新增更强复核模型属于审核能力，不是增加生产OCR后端；仍需资源和资料访问授权。量化、不同精度、GPU后端、服务版本都记录身份，改变后重新检查关键样本。

### 5.4 限制无效循环

初版采用首审一次＋有新源证据/独立读取的复审一次；仍有分歧就UNRESOLVED。HTTP传输失败可按已有重试策略有限重试，但不能靠重复采样到赞同才通过。格式错误先看契约/长度；模型看不清时先换清晰源区域，不盲目增加Token或反复问同一句。

不要用新增通用Agent平台、整段视频长上下文、每页重抄全文、无条件双模型全量复核来解决效率问题。

## 6. 准确度控制：源覆盖、内容读取和输出保真分别验收

无法仅靠模型名称、一次自信分数、temperature=0、两个回答一致或合法JSON保证100%正确。需要以下分开的验收层：

| 层 | 检查 | 不可冒充的结论 |
|---|---|---|
| 源覆盖 | 独立源范围、短暂变化、重复映射、边界和未审区域 | 选中帧全部处理不等于全片资料无遗漏 |
| 文字/字段 | 对原图逐字；保留标点、大小写、下划线、前导零、否定词及先后顺序 | OCR/VLM置信度高不等于关键字段正确 |
| 表格/图片 | 行列归属、合并、父级表头、全图/接缝和遮挡 | 格数正确或图像文件存在不等于结构完整 |
| 修正行为 | 修改前后与源证据对应；统计纠正和误改 | 改动有哈希/可回滚不等于改得对 |
| Office交付 | 实际文件中逐字/逐格保留，渲染检查裁断、分页、窄列 | reviewed JSON正确不等于Word/Excel正确 |

关键技术字段包括寄存器名、地址、位宽、复位值、时序、极性、否定和先后顺序。初期这些字段全量独立源核对，而不只是拟修改字段；如此才能发现“原本就错、模型没有提出修正”的问题。第二次源读取不展示第一次答案。若两次仍不一致或源模糊，必须人工/独立可信源确认；没有此条件就保留未决并拒绝完整通过。

普通内容首轮仍完整覆盖，可对模型标成无变化的内容做源图抽检，并抽检被判重复的区域；抽检用于估计风险，不据抽检通过声称所有未查项准确。发现漏项或误改要扩大该类检查。

独立验收真值不提供给修正模型。现有8条LIMIT真值只能用于评价，不能由复核模型看答案再宣称识别改善。首批8条只是技术试验集，不足以证明密集表格或其他视频泛化。

寄存器地址递增、位宽和值范围、章节编号连续性只能报警，不能据规律自动补齐。图中没有的内容保持缺口。

## 7. 怎样证明既快又准

在同一代表性源集合、同一硬件/服务限制下记录三组：原工具初稿；未经效率优化的工具＋视觉核对；启用分块/缓存/批处理后的工具＋视觉核对。历史已有结果可直接复用，不重新运行已完成OCR来凑组数。

代表性集合至少覆盖完整8条约束、一个正常普通表、一个已知异常普通表、一份密集表样本、一张完整图及一个跨画面边界。继续保留独立未用于调参的资料单元作为后续检验；不反复围绕同一张MemoryMap筛参数。

| 记录项 | 口径 |
|---|---|
| 端到端耗时 | 从既定输入可用到完整成果及未决清单落盘；冷启动安装/下载、模型初始化与热运行分开；重试/渲染/复核不能漏计 |
| 新内容处理量 | 原观察数、独立源单元数、合并重复候选数、实际复核调用数分别记录，不互换分母 |
| 输入/输出成本 | 文本Token、视觉Token（可取才填）、图片像素、输出Token、付费接口费用或机器资源时间；未提供的指标写未知，不按JPG字节数猜Token |
| 有效吞吐 | 已有效复核的源单元/分钟；完整章节及最终资料通过数另列，不能将一次API成功计为内容通过 |
| 误差 | 初稿错误数、正确修正数、错误修正数、残留/新增遗漏、关键字段错误/未决、表格位置及合并错误 |
| 覆盖与人工负担 | 未审源范围、选择误丢、被抽检的无变化/重复范围、需人工确认项；看不清不算正确 |

接受原则：内容/覆盖的硬门禁先于速度；关键字段出现错误自动修改就停止该类自动放行。能否达到某个百分比或倍数必须报告样本数、风险类别和实际测量，不写未经测量的99%/10倍。

质量-效率选择采用同范围对照：在不增加已知漏项/误改且不扩大未决范围的候选中选端到端耗时/成本更低者；不能用把难题全部拒绝或跳过来制造高准确率。小样本零误改只说明该样本观察，不保证未来零错误。

## 8. 测试机一次整包完成，不新增聊天批准点
