# EFC：ET6601 修改点总览

更新：2026-10-05。仅依据本仓库EFC的24张LRS与36张LLD原始截图；不使用其他芯片手册、代码或常识补齐。

## 1. 阅读入口与判定边界

[EFC LRS完整还原](efc_lrs/docs/EFC模块LRS设计文档.md)的第二部分保存25条原文记录；
[EFC LLD完整还原](efc_lld/docs/EFC详细设计文档.md)的第二部分保存52条原文记录。
下面按主题建立索引，**77条是原文出现位置记录，不是77个独立功能变更**。同一主题在接口表、正文、修订表出现多次，分别回链，不重复推断功能。

只有原文明确写出“新增、回退、修改、删除”时，才按该性质描述。红字本身只能证明该处标红；蓝字单列为作者说明，不能自动计为6601版本差异。LRS的4条、LLD的16条蓝字均仍在各自正文第二部分，不混入77条。

文档的编号、分区容量、保护粒度、信号拼写和时钟范围存在原文差异；这里并列呈现，不选择一个数值覆盖另一处。尚未辨明的5组小字详见[EFC提取与验收报告](EFC_提取与验收报告.md)。

## 2. 按主题归集的修改内容

| 主题 | 原图明确表达的内容 | 原文定位 | 归类限制 |
|---|---|---|---|
| 修订基线及Flash组成 | 修订表1.1明确“新增64KX72=512KB的PFLASH，原有FLASH回退为DFLASH”；LRS另列一个512KB PFLASH、一个128KB DFLASH | LRS C01/C02/C25；LLD C01/C02 | LRS修订日期20260920，LLD为20260922，分别保留；C01是来源基线，不是功能新增 |
| PFLASH双BANK与访问接口 | PFLASH Main 512KB，BANK0为0x000000–0x03FFFF，BANK1为0x040000–0x07FFFF；SYSC SWAP交换AXI读写地址，APB间接命令不交换；一个PFLASH、一个DFLASH分别使用AXI接口，支持DMA访问 | LRS C10/C11/C15 | 这是截图红字的事实归集，不推断未给出的旧地址和旧接口数量 |
| NVR间接读取 | “NVR、NVR_CFG读取，需要进行间接寻址，避免总线ready拉低挂住系统” | LRS C03 | 原图未明确写“新增”，不擅自赋予新增性质 |
| 用户OTP及保护 | USER OTP在nvr sector9~13，变为OTP后禁止擦除、上电自动生效；另述擦除sector14可恢复；TEST_CODE!=0时不做保护；双重下标与sector编号照录 | LRS C04/C06/C07/C08/C16/C19/C24；LLD C19/C23/C28 | LRS某处仍写“3个sector（3KB）”，另处明确5KB/sector9~13；属于原文冲突，不偷偷统一 |
| MAIN与NVR保护粒度 | PFLASH main不受rdp保护、受wrp保护；DFLASH main某处标出sector/16KB；NVR_CFG解锁值在不同表中有0x00、0x5A差异 | LRS C05/C09/C17/C20；LLD C08/C16/C17/C20/C21 | PFLASH“整片”与后文“sector/32KB”都保存；不同表的保护值不互相覆盖 |
| Boot、ROM/OTP访问及UID | rom_rd_en、sysc_boot_exit_lockj红字；UID为uid[255:0]且255标红；ROM/OTP锁存信息“并进行多数判决”；输出CPLD使能/调试禁止 | LRS C18；LLD C03–C07/C24–C27/C29/C30/C33–C35 | 255标红不代表能够推断旧位宽；末尾j及双重下标不改名 |
| 启动选项删除 | 左右页两处nSWBOOT1,nBOOT1均被删除线划去 | LLD C18/C22 | 是两个来源位置，不按两项独立删除功能计数 |
| 整芯片擦除与冗余 | 擦除次序中的pflash main+RDN、USER OPTION sector8、USER OTP sector9~13标红；PFLASH/DFLASH冗余替换描述保留 | LRS C21–C23；LLD C09/C12/C31/C32 | LRS完整次序与LLD完整次序各自在原文，不改造成同一份推断流程 |
| ECC使能要求 | “非64bit操作不使能ECC”在原图中被删除；MAIN/NVR/NVR_CFG ECC默认开启并禁止配置关闭；PFLASH/DFLASH对应8bit ECC | LRS C12–C14 | 删除线必须保留，不能把被划去的条件当有效要求 |
| ECC域段取反 | 开启ECC及ECC_WR_RVS/ECC_RD_RVS时，对ECC第0、1、4–7bit取反；原文用8’hC→8’hFF说明全1数据；读回按原文取反校验 | LLD C50/C51；图2-15/2-16 | 正文RVS与图中rsv、图2-16也叫“写入图”均照录；图2-15控制信号小字仍有U11 |
| 复位、时钟和初始化完成 | por_rst_n/flash_por_rst_n说明标红，nvr_shift_done及超时机制标红；CORE频率变化时FLASH时钟随之变化，按timing计算IDS值 | LLD C10/C11/C13–C15/C36 | 原文25～200MHz、接口25～100MHz等范围不强行调和 |
| 读采样与tMH问题 | 明确“将读采样修改为efc_clk，提高读效率”；指出每次末次读后都等待tMH降低性能，以及READ MODE CHANGE等待尚未生效问题 | LLD C37–C44 | 路径、标题与问题说明也有独立来源编号，不能都当作独立功能 |
| 明确列出的四项ET6601优化 | ①仅Recall Read等待tMH，Normal Read/Vread1不等待；②VREAD1拉高修改到tNVS之后；③Program/ERASE时Recall拉低；④仅根据VREAD1/Recall变化决定是否等待tMS | LLD C45–C49；第26/27张 | 第③项原文写“与ET6601方案保持一致”，不包装成新增；第26张代码保留原符号，不通过逻辑推理修复 |
| BOOTROM外部要求删除 | 第5章第10行PR0、PR1读取及配置替换内容的要求整行有删除线 | LLD C52 | 数字0是PR0，不是字母O的PRO；删除内容仍留在原表以便核对 |
